# Exemplo 2D

O exemplo `examples/2d/` descreve **Starfall Courier**, um pequeno jogo 2D
orientado a sprites. Ele combina um asset de personagem, um perfil de captura
customizado, jobs para asset/componente/estado, uma referência ainda pendente
de aprovação e uma folha técnica declarativa.

## O que é customizado

`project/profiles/courier-sprite.json` é um `capture-profile` v1 explícito do
projeto. Ele usa câmera ortográfica, fundo transparente, iluminação flat e
canvas 256×256, além de exigir os componentes `subject` e `body` e os estados
`idle` e `run`. O perfil é validado pelo mesmo contrato usado pela aplicação;
não existe um catálogo paralelo nem uma constante Python específica do exemplo.

A persistência e seleção de catálogos de perfis locais ainda pertencem a uma
etapa futura. Por isso o exemplo mantém o perfil como entrada auditável e o
passa explicitamente ao planejador nos testes.

## Fluxo

Inicialize o projeto com o PR19 e copie as entradas do exemplo:

```bash
ludowright init ./starfall-courier --name "Starfall Courier" \
  --template minimal --non-interactive
cp -R examples/2d/project/. ./starfall-courier/
```

Valide os contratos e o perfil antes de registrar o asset ou planejar jobs:

```bash
ludowright assets create ./starfall-courier --input imports/courier.json
```

O plano deve permanecer bloqueado enquanto
`imports/courier-reference.json` estiver `candidate`. Uma aprovação humana
precisa ser aplicada ao mesmo `reference_id` e à mesma revisão antes de
produzir uma sheet ou executar geração.

O PNG textual em `fixtures/courier-front.png.b64` é uma fixture determinística
de 16×16 pixels. O request da sheet registra seu SHA-256, mas os arquivos
normalizados e a sheet continuam sendo artefatos derivados, não estado oculto
versionado no repositório.

## Compatibilidade

O exemplo usa somente contratos v1 já publicados. Não altera schemas,
migrações, SQLite, event log, dependency graph ou o catálogo de perfis
empacotado.
