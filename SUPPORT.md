# Support

LudoWright is currently pre-alpha. Support is community-driven and best-effort.

## Before asking for help

Check:

1. `README.md`;
2. `PROJECT_START.md`;
3. `docs/ATLAS.md`;
4. existing issues and discussions;
5. the output of `ludowright --version` and `ludowright status --json`.

## Where to ask

Use a GitHub issue when you have:

- a reproducible bug;
- incorrect documentation;
- an installation problem that appears to be a project defect;
- a concrete feature proposal.

Use GitHub Discussions, when enabled, for:

- general questions;
- workflow advice;
- examples and showcase posts;
- design discussions that are not yet actionable issues.

Use private vulnerability reporting for security problems. See `SECURITY.md`.

## Information to include

Provide:

- LudoWright version or commit;
- Python and `uv` versions;
- operating system;
- command executed;
- expected behavior;
- actual behavior;
- minimal reproduction;
- relevant logs with secrets removed;
- project schema version when applicable.

Do not upload private assets, credentials, personal information, or copyrighted reference material you cannot share.

## Unsupported requests

Maintainers cannot guarantee help with:

- unofficial forks or modified builds;
- unsupported Python versions;
- failures caused by external AI services;
- proprietary engine or DCC integrations not maintained here;
- prompts or generated content that violate applicable policies;
- custom plugins that have not isolated a reproducible core defect.

## Compatibility

Before `1.0`, interfaces may change between minor releases. Upgrade notes and migrations will become progressively stricter as persisted project formats stabilize.
